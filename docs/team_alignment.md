# 팀 합의 체크리스트 (캡스톤)

이 문서는 아래 5개 파트가 최소한으로 맞춰야 하는 합의 항목을 정의한다.

1. 공통
2. 프론트엔드
3. 백엔드
4. 스트리밍
5. IoT

기준 범위는 런타임 v2(`src/capruntime`)이며, 원칙은 `프로세스 1개 = 카메라 1대`이고 센서는 동일 프로세스에 여러 개 붙을 수 있다.

## 1) 공통 합의 (전 파트)

- 카메라 단위 규칙: 카메라 1대당 런타임 프로세스 1개 사용 (`camera_id`는 유일 키).
- 시간 표준: 이벤트 타임스탬프는 모두 UTC ISO8601 형식 사용.
- 환경변수 표준: `CR_*`만 사용 (`AI_*`는 지원하지 않음).
- 전달 신뢰성: 백엔드 장애가 나도 런타임은 멈추지 않아야 하며 spool fallback은 필수.
- 범위 경계:
  - 본 레포는 카메라/센서 입력부터 백엔드 이벤트 전달까지 담당
  - 프론트의 정책 UI, 최종 알림 정책 판단은 본 레포 범위 밖

### 이벤트 스키마 최소 계약

- `event_id` (문자열 UUID)
- `ts` (UTC ISO8601)
- `site_id` (문자열)
- `camera_id` (문자열)
- `event_type` (문자열)
- `object_type` (문자열)
- `severity` (문자열)
- `track_id` (문자열 또는 정수 또는 null)
- `confidence` (실수)
- `bbox` (`x1,y1,x2,y2` 정수)
- `zone` 객체 (`zone_id`, `inside`)
- `sensors` 객체 (센서 이름 키 기반)

## 2) 프론트엔드 합의

- 런타임 프로세스에서 직접 영상을 받는다고 가정하지 말고, 스트리밍 파트가 승인한 스트림 경로를 사용.
- 이벤트 누락/지연 상태를 안전하게 렌더링:
  - 이벤트 없음
  - 이벤트 지연
  - 백엔드 재연결 구간
- 화면 키는 반드시 `event_id` 사용(로컬 임의 키 금지).
- 색상/라벨 매핑은 백엔드 이벤트 타입 사전과 일치시킬 것.

프론트 파트 산출물:

- 이벤트 타입 to UI 라벨 표
- stale 데이터 경고 뱃지 타임아웃 기준

## 3) 백엔드 합의

- 캡스톤 기준 수신 엔드포인트 고정:
  - `POST /api/events` (JSON, 요청 1건당 이벤트 1개)
- 응답 계약:
  - 2xx: 수신 성공
  - non-2xx: 런타임이 로컬 spool에 유지
- `event_id` 기준 멱등 처리(중복 안전 저장) 지원.
- 프론트와 공유할 이벤트 타입 사전 제공.
- 이벤트/스냅샷 보관 정책(향후 스냅샷 활성화 포함) 정의.

백엔드 파트 산출물:

- API 명세(요청/응답 예시, 오류 코드)
- `event_id` 중복 처리 규칙
- 런타임 스키마 매핑 DB 필드 목록

## 4) 스트리밍 합의

- RTSP 엔드포인트 소유권은 스트리밍 파트가 가진다.
- 런타임이 안정적으로 사용할 카메라별 URL 매핑을 제공:
  - 예: `rtsp://<host>:8554/cam1`, `.../cam2`
- 스트림 장애 동작:
  - 일시 단절은 런타임 재시작 없이 복구되어야 함
  - 스트리밍 파트가 재기동/헬스체크 명령 제공
- 코덱/지연(latency) 프로파일 문서화 필수(프론트/런타임 튜닝 기준).

스트리밍 파트 산출물:

- 카메라별 RTSP URL 레지스트리
- 재기동 절차와 헬스체크 명령
- 코덱/FPS/해상도 프로파일

## 5) IoT 합의

- 센서 네이밍 규칙: 카메라 프로세스 단위로 `name` 유일해야 함.
- 센서 페이로드는 JSON 객체 형식만 허용(평문 문자열 금지).
- 센서별 송신 주기(`interval_sec`)를 사전에 선언.
- 센서 장애 격리:
  - 센서 1개 실패가 카메라 루프를 막으면 안 됨
  - stale 센서 데이터 처리 기준(타임아웃) 합의 필요

IoT 파트 산출물:

- 센서 카탈로그(이름/타입/단위/주기)
- 센서별 페이로드 예시
- 장애 의미 정의(`null`, stale, 범위초과 등)

## 런타임 v2 전환으로 재합의가 필요한 항목

- 플러그인 경로 기반 런타임 로딩은 캡스톤 트랙에서 제거됨.
- 모델 선택은 내부 스위치만 사용: `mock | yolo | onnx`.
- 배포 방식이 카메라 인스턴스별 `systemd` 템플릿으로 변경됨.
- 검증 기준 문서가 아래로 고정됨:
  - `docs/demo_scenarios.md`
  - `docs/performance_report.md`
  - `docs/operations.md`
